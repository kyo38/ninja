# Scion → Ninja: ポジショニング & 技術的差別化

本ドキュメントでは、既存の主要な分散タスク実行基盤・ワークフローエンジン（Apache Airflow, Ray, Kubernetes Jobs）と `ninja` のポジショニングおよび差別化ポイントについて整理します。

---

## 1. 開発背景とコンセプト

`ninja` は、巨大なインフラや複雑な事前セットアップを必要とせず、**「単一バイナリ・超低レイテンシ・ローカル/閉域網環境」** で確実に動作する分散 DAG 実行エンジンを目指して設計されています。

---

## 2. 他システムとの詳細比較

| 比較軸 | Apache Airflow | Ray | Kubernetes Jobs | **Scion → Ninja** |
| :--- | :--- | :--- | :--- | :--- |
| **主な用途** | 重厚なETL / バッチ処理 | Python中心のML/AI分散計算 | コンテナ単位の独立タスク | **軽量・低レイテンシ分散DAG制御** |
| **言語・ランタイム** | Python | Python / C++ | コンテナ（Docker等） | **Rust (Tokio)** |
| **依存インフラ** | 外部DB (PostgreSQL等), Web | 専用クラスタ / Ray Head | Kubernetes クラスタ | **なし (単一バイナリで完結)** |
| **スケジューリング精度** | 分単位〜数秒単位 | ミリ秒単位 | 数秒〜数分 (Pod起爆) | **ミリ秒単位** |
| **オーバーヘッド** | 大 (DB同期・Python) | 中 (Ray Agent管理) | 極大 (コンテナ起動/破棄) | **極小 (TCP/JSONプロトコル)** |
| **動作環境** | Linux中心 | Linux中心 | K8s環境必須 | **Windows 11 / Linux (エッジ対応)** |

---

## 3. `ninja` が提供する固有の価値 (Value Proposition)

### ① 超軽量・ゼロデプロイコスト
外部データベースやコンテナランタイムを一切必要としません。Rust でビルドされた単一のバイナリを配置するだけで、数MBのメモリフットプリントで即座に動作します。

### ② 閉域網・ローカル環境におけるミリ秒駆動
K8s やクラウド基盤を導入できないスタンドアロン環境（工場・エッジ・ローカルWindows 11開発基盤）において、プロセスのミリ秒単位の依存関係制御と順序保証を実現します。

### ③ 言語・環境に依存しない汎用プロセス制御
Python ランタイム等に依存せず、OSのネイティブコマンドや各種バイナリをDAGのノードとして透過的に実行・監視できます。

---

## 4. エレベーターピッチ（一言での明確な定義）

> 「AirflowやKubernetesを構築・運用するほどのオーバーヘッドは許容できないが、ローカルやエッジ環境でミリ秒単位の順序保証と死体検知・自動再割り当てを備えた堅牢なDAGタスク実行基盤が必要な現場のための、Rust製・単一バイナリ分散スケジューラ」
