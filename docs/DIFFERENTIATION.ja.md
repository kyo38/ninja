# ポジショニング & 技術的差別化

## 課題 (Problem)

Apache Airflow、Ray、Kubernetes Jobs などの既存の分散タスク管理システムは非常に強力ですが、大きな運用複雑性、重厚な外部依存関係、高いランタイムオーバーヘッドを伴うことが多く、軽量・実験的・あるいはセキュリティ要件の厳しい環境には適さないケースがあります。

## アプローチ (Approach)

**Ninja** は以下のコンセプトで設計されています：

- **軽量 (Lightweight)**
- **Rust製 (Rust-based)**
- **分散DAG実行エンジン (Distributed DAG execution engine)**

単純性（Simplicity）、厳格な制御権限（Control）、そして拡張性（Extensibility）に特化しています。

## 主な差別化ポイント

### 1. 徹底した軽量設計 (Lightweight by Design)
外部データベース（PostgreSQL等）を一切必要とせず、ランタイムオーバーヘッドを極小化。Rust で構築され、数メガバイトのメモリフットプリントで即座に動作します。

### 2. DAGファーストの実行モデル (DAG-first Execution Model)
入次数計算と動的トポロジカルソートによる明確な依存関係解決を行い、確実なタスク実行順序を保証します。

### 3. 本格的な分散オーケストレーション (True Distributed Orchestration)
中央集権型 Master スケジューラによる動的 Worker プール管理、双方向 12 秒 PING/PONG ハートビート死体検知、および Worker 離脱時の自動タスク再割り当て（Re-queue）を備えています。

### 4. 組み込みの可観測性 (Observability Built-in)
`tracing::span` による非同期コンテキストを維持した構造化ログ出力に加え、組み込み Axum Web ダッシュボードによるリアルタイム状態監視を提供します。

### 5. 高い拡張性 (Extensibility)
外部定義ファイル（JSON / YAML / TOML）のロードや、OSネイティブプロセス実行に対応したプラグインアソシエートなアーキテクチャを採用しています。

## ポジショニング (Positioning)

Ninja は Airflow や Kubernetes のような大規模オーケストレーションシステムを置き換えることを目的とするものではなく、以下のようなシナリオにおいてそれらを補完・代替するシステムです：

- **単純性・シンプルさが求められる場合 (Simplicity is required)**: 複雑な事前構築や外部データベース接続を一切必要とせず、運用コストを最小化。
- **完全な制御が必要な場合 (Full control is needed)**: プロセス管理、厳格なDAG実行順序、タイムアウト制御、および低レイヤー通信を直接ハンドリング。
- **インフラ環境に制約がある場合 (Infrastructure is constrained)**: エッジノード、閉域網・オフライン環境、ローカル開発環境、リソース制約のある Windows 11 / Linux 環境に最適。

特に以下の用途に最適化されています：
- **研究・実験環境**: 非同期分散アルゴリズムの高速なプロトタイピング
- **セキュア & 閉域網システム**: 外部クラウドやコンテナランタイムに依存しないスタンドアロン実行
- **組み込みタスク実行エンジン**: 高速・ミリ秒駆動の DAG スケジューラをツールチェーンに直接組み込む用途
