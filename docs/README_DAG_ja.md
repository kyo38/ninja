# DAGエンジンの概要とSCIONアーキテクチャにおける応用

本書は、DAG（有向非巡回グラフ）エンジンの基本原理と主要な用途、および次世代インターネットアーキテクチャ **SCION** における思想と応用方法についてまとめたドキュメントです。

---

## 1. DAG（有向非巡回グラフ）エンジンの基本概念

### 概要
データを「一方向（有向 / Directed）」かつ「循環・ループしない（非巡回 / Acyclic）」関係性（グラフ構造 / Graph）として定義し、その依存関係に基づいてタスクの実行順序を制御・管理する仕組みです。

### 原理（動作メカニズム）
- **ノードとエッジ**: 
  各タスクやデータ要素を「ノード（点）」、タスク間の依存関係やデータの流れを「エッジ（矢印）」で表現します。
- **トポロジカルソート**: 
  依存関係を自動計算し、「どの前提タスクが終われば次のタスクを開始できるか」を正確な実行順序として算出します。
- **並列性と安全性**: 
  互いに依存しないタスクは安全に並列実行可能です。また、循環構造を持たないため、無限ループやデッドロックを構造的に防ぎます。

### 主な用途
- **データパイプライン / ETL**: 分散データ処理における依存関係の管理（例: Apache Airflow, Prefect, dbt）。
- **ワークフローオーケストレーション**: CI/CDパイプラインや複雑な分散システムでのタスク順序制御。
- **ブロックチェーン / 分散台帳**: トランザクションを網の目状に依存・承認させることによる高速化と拡張（例: IOTA, Fantom）。
- **機械学習 / AIの計算グラフ**: ディープラーニングにおける順伝播・逆伝播（勾配計算）のグラフ実行。

## 2. SCIONアーキテクチャにおける思想とDAGの応用

### SCIONにおける根本思想
現在のインターネット（BGPルーティング）は「ルーターが手探りで次の行き先を決める（Hop-by-Hop）」ため、経路ハイジャックやセキュリティリスク、障害発生時の迂回遅延などの課題を抱えています。

これに対し **SCION**（Scalability, Control, and Isolation On Next-generation networks）は、**「送信者が通信経路（パス）を事前に完全にコントロールし、検証可能にする（Path-Aware Networking）」**という思想に基づいています。この思想を実現する構造的基盤として、DAGおよびグラフ構造が不可欠な役割を果たします。

### SCIONにおけるDAG / グラフ構造の使われ方

1. **経路セグメントの組み合わせ（Up / Core / Down セグメント）**
   SCIONではドメイン（ISD/AS）間を結ぶ経路を、方向性を持ったセグメントとして事前生成します：
   - **Up-Segment**: 発信元からコア組織へ向かうパス
   - **Core-Segment**: コア組織間を結ぶパス
   - **Down-Segment**: コア組織から目的地へ向かうパス
   
   送信者はこれらの有向セグメントをパズルのように組み合わせ、ループのないエンドツーエンドの経路（Path）を構築してパケットヘッダーに埋め込みます。

2. **レジリエンスとマルチパス（高速フェイルオーバー）**
   トポロジーを有向グラフとして管理することにより、特定リンクの障害時にも代替ルート（別のグラフ枝）へ即座に切り替える（高速フェイルオーバー）ことができ、複数経路を用いた同時送信（マルチパス通信）も容易になります。

3. **暗号学的検証と循環防止**
   有向グラフ上の各遷移は暗号学的（MAC）に保護されています。万が一、逆流や不正な循環（ループ）を含むパスが作成されても、検証フェーズで即座に検出・排除されます。

---

## まとめ
- **思想**: 通信の主権を取り戻し、安全で信頼できる道筋を送信者自身が選択する。
- **DAGの役割**: ループのない安全な「経路パーツ」を組み合わせ、確実で障害に強いルーティングを実現するための構造基盤。
